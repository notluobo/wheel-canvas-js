# 本地化规范

[English](../LOCALIZATION.md) · 简体中文

## 语言结构

- `README.md` 是 GitHub 默认展示的简体中文仓库主入口。
- `README.en.md` 是英文仓库入口。
- `docs/` 下稳定文件名保存英文文档。
- 简体中文文档集中放在 `docs/zh-CN/`，文件名与英文文档保持一致。
- 工作台共用同一套 DOM 与 JavaScript 实现，翻译集中在 `demo/i18n.js`，不会进入核心 UMD/ESM 包。
- `?lang=en` 与 `?lang=zh-CN` 是稳定链接；没有查询参数时，优先使用上次明确选择，其次使用浏览器语言。

## 内容规则

- 运行时标识符、配置值、文件名、npm 命令、错误名称和代码语法保持英文，不翻译。
- 说明文字、控件标签、无障碍名称、状态消息和教程正文必须本地化。
- 新增公开契约时以英文语义为准，同一 Pull Request 必须同步简体中文。
- 翻译可以优化自然表达，但不得增加、删除或改变运行行为。
- 示例中的可见奖项名称可以本地化，API 结构必须保持一致。

## Pull Request 检查

- [ ] 两个 README 在标题附近互相链接。
- [ ] 两份配置文档拥有相同的公开 API 章节。
- [ ] 两份版本记录包含同一个版本号。
- [ ] 工作台新增文字有英文翻译。
- [ ] 无障碍标签、动态错误和状态消息已经翻译。
- [ ] `npm test` 的本地化契约通过。
- [ ] 两种语言均在移动端和桌面端人工检查。

## 增加其他语言

使用 BCP 47 语言标签，增加可见语言入口，提供对应 README/文档，扩展工作台语言目录，并加入一致性测试。不得按语言分叉核心行为。
